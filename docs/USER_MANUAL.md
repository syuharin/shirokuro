# Shirokuro ユーザマニュアル

Shirokuroは、数値同期に特化した、シンプルかつ強力なP2P同期アプリケーションです。データベースやサーバーを介さず、WebRTC（PeerJS）技術を用いて参加者間の数値をリアルタイムに共有します。

---

## 1. セットアップ（開発者・上級者向け）

ローカル環境で実行する場合は、Node.js環境が必要です。以下の手順で依存関係をインストールし、実行してください。
```bash
# 依存関係のインストール
npm install

# 開発サーバーの起動
npm run dev
```

ブラウザで `http://localhost:3000` にアクセスしてください。

---

## 2. 基本的な使い方

### 部屋（グループ）の作成
1. トップページ（`http://localhost:3000`）にアクセスします。
2. **[Create Group]** ボタンを押します。
3. 自動的に生成された固有のURL（例: `/room/abc-123-xyz`）に遷移します。

### URLの共有
1. 右上の **[Share URL]** ボタンを押すと、招待用URLがクリップボードにコピーされます。
2. 表示されるQRコードをスマホ等でスキャンしてもURLを取得できます。
3. 他の参加者がこのURLにアクセスすることで、同じ部屋にP2Pで接続されます。

### 名前の設定
1. **[Display Name]** 入力欄に自分の名前を入力します。
2. 名前は即座に他の参加者へ同期されます。

### スライダーの操作
1. 画面中央の **スライダー** を左右にドラッグして値を設定します。
2. スライダーから手を離したタイミングで、最終的な値が他の参加者に同期されます。
3. 他の参加者の値は **分布バー** 上に各ユーザーの名前と共に表示されます。

---

## 3. 高度な機能：ホスト移行ロジック

Shirokuroは、特定のサーバーを持たない分散型P2P設計を採用していますが、部屋の接続を維持するために「ホスト（Anchor）」という役割が存在します。

*   **自動ホスト選出**: 元のホストがブラウザを閉じたり、通信が切断された場合、残った参加者の中から新しいホストが自動的に選出されます。
*   **セッションの継続**: ホストが退出しても、既存の参加者間の接続は維持され、数値の同期はそのまま継続されます。
*   **部屋の再公開**: 新しいホストは、元の固定URL（固定ID）を再取得しようと試みます。再取得が完了すると、そのURLから新しい参加者が再び入室できるようになります。
*   **ステータス表示**: ホストの交代中や再設定中は、画面上部に「ホストが交代しました。新しい参加者を待機中です」といった通知が表示されます。この間もスライダー操作は通常通り行えます。

---

## 4. 信頼性と接続に関する注意

*   **接続の維持**: WebRTC技術の特性上、参加者が増えると通信負荷が高まる場合があります。通常、数人〜10人程度のグループでの利用を推奨します。
*   **プライバシー**: データはサーバーに保存されません。ブラウザを閉じるとそのセッションのデータは消去されますが、同じURLであれば前回の設定（名前など）が一部復元される場合があります。
