# Data Model: Real-time slider sync

**Feature**: 001-realtime-slider-sync
**Status**: Design
**Date**: 2026-02-22

## Peer (Transient State)
The primary data entity is the Peer, which exists only in memory and via WebRTC data channel payloads.

| Field | Type | Description |
|-------|------|-------------|
| peerId | string | Unique WebRTC ID generated by PeerJS. |
| name | string | User-provided display name (e.g., "Alice"). |
| value | number | The current slider value (0-100). |
| isSelf | boolean | Flag for the current local user. |
| lastUpdated | timestamp | For tracking heartbeats or message order. |

## Room (Logical Context)
The Room is not a stored entity but a logical grouping derived from the URL path.

| Field | Type | Source |
|-------|------|--------|
| roomId | string | URL parameter `[id]`. |
| participants | map<string, Peer> | Map of all active peers in the current mesh. |

## State Transitions
- **Join**: 
  - User visits `/room/[id]`.
  - Generates PeerID `shirokuro-[roomId]-[short-uuid]`.
  - Connects to "Discovery Peer" (the lobby-anchor).
  - Receives list of other PeerIDs.
  - Connects to all other PeerIDs to form a full-mesh.
- **Update**: 
  - Local user drags slider to 75.
  - On `onMouseUp`, local state updates `value: 75`.
  - Sends `{ type: 'SYNC_UPDATE', peerId: '...', value: 75, name: '...' }` to all open DataChannels.
- **Leave**: 
  - User closes browser tab.
  - WebRTC `DataChannel` fires `on('close')`.
  - Remaining peers remove that `peerId` from their local `participants` map.
- **Name Change**:
  - User edits name input.
  - Local state updates `name`.
  - Broadcasts `{ type: 'SYNC_UPDATE', peerId: '...', value: [currentValue], name: '[newName]' }`.
